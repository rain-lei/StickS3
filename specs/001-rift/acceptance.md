# 首版验收计划

每次验证记录固件版本、设备数和结果。主机、目标构建、实体联调分别取证。硬件测量从正对、距离至少 30 cm 开始，然后改变距离、角度与环境光。

| 需求 | 主机或构建时验证 | StickS3 实机验收 |
|---|---|---|
| R1 | 检查训练和通关奖励只提交一次。 | 观察待机休眠、摇晃唤醒和成长外观。断电重启后对比精通、经验、胜场、符文和三个槽。 |
| R2 | 注入静止、横挥、前推、转腕、完整圆轨迹与先圈后推；比较持续、间歇及无声输入。 | 同一人各做十次，记录误识、漏识与能量变化。验证 A 松开只释放一次，错误动作有重试提示。 |
| R3 | 检查 Boss 属性预告、治疗、护盾、胜利与失败。 | 单机胜利后选中绑定的灯光槽，挥杖触发；失败返回，检查奖励计数。用匹配和错误的遥控键分别挑战。 |
| R4 | 模拟握手、丢包重发、乱序、重复结果、错房间、错攻击序号、红外超时及格挡。 | 双机先正对命中，再遮住整个红外窗、切断双向光路验证未中。格挡后比对两屏血量；中途关闭一方再重新建房。 |
| R5 | 两个客户端通过同一房主快照递进，检查队友治疗和 Boss 终局。 | 双机轮流施法直到胜利，两端回巢并核对各自奖励。 |
| R6 | 对 NEC 标准/扩展地址、错误脉宽、游戏帧及短重复码进行编解码测试。 | 三槽各学一个不同的遥控键，学习超时后核查旧槽，重新上电并逐槽试发。 |
| R7 | 构建 StickS3 固件，检查 RMT 配置、功放和麦克风的状态转换。 | 对齐施法、就绪、红外到达、无线结算和音效五个时刻，记录切换耗时与丢失次数。确认接收期间功放关闭。 |

## 通过条件

双板光路复测使用两台板实际的 RMT 收发函数，串口只触发发送和记录结果。两台在巢穴中正对，分别轮流发送不同的攻击令牌，记录完整匹配次数、重发次数及各次收到的片段掩码。此项和完整按键、动作、无线决斗分别验收。

决斗漏判回归覆盖双方同时进攻、不同技能独立冷却、叠盾上限、消耗一层盾后的反击和重复报告。按索引验证光学符号，同一方向可跨重发补齐八个位置中的任意六个。正向未匹配时启动反向回探。两个方向各自匹配的位置都不足六个时按未命中结算，包括错令牌和两条光路完全遮挡的情况。另行验证 NEC 学习与机关重放。

额外验证决斗演示路径。两端分别扮演攻守方，守方启用一个已学灯光槽。火斩命中护盾时，守方发一次指令；遮挡红外、重复结算或关闭联动时发零次。记录两台屏幕、灯光与音效出现的顺序。

首版规格中的每个行为都要有对应实现。主机用例通过且固件成功链接后可进入实机阶段。物理命中率、手势阈值、声音阈值与遥控兼容性以实测记录为准。首次文档提交用于锁定这些条件。
